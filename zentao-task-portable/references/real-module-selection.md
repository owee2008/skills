# 真实禅道模块匹配规则

用于把用户提供的模块名称安全解析为目标项目中的真实 leaf 模块。

## 核心要求

- 名称解析必须基于预检时的实时项目创建页，历史映射只用于构造请求名称。
- 命名模块只在 leaf modules 中匹配；明确给出的数值模块 ID 仍需验证属于目标项目。
- 唯一命中才能进入 `status=ready` 的批准计划；零个或多个命中返回 `needs_confirmation` 和相关候选，绝不创建任务。

## 操作流程

1. 把用户提供的服务、项目名称、模块名称和负责人写入请求 JSON。
2. 运行一次 `--batch-json request.json --dry-run`，由预检直接读取实时模块并返回唯一结果或相关候选。
3. 唯一命中时，使用输出中的真实模块路径和 ID 展示确认清单。
4. 歧义时只展示 `ambiguities` 中的候选；用户选择后更新请求并重新预检。
5. 用户确认 `status=ready` 的版本化计划后，使用 `--approved-plan` 执行。

## 表述规范

- 唯一命中：“预检实时解析为 `/语音沟通/视频会议`（ID: 2948）。”
- 歧义：“预检返回 2 个相关 leaf 模块，请选择其一。”
- 实时预检失败时明确停止，不把历史模块称为真实模块。
