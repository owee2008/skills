# 田一禅道“APP装车”项目歧义与创建校验

## 适用场景

用户用“APP装车”“装车 APP”“自动装车”等口语名称指定田一禅道项目时，用本页帮助消歧。项目和成员信息仍须在执行时实时查询。

## 容易混淆的项目

- `1685`：`头盔自动装车APP开发`
  - 2026-08-01 实时查询到任务 leaf 模块：`/软件开发`（`9750`）。
  - 张斌账号 `zhangbin` 当时在任务创建页负责人下拉中可选。
  - TYBox、Coze Workflow、头盔扫码/拍照/装车流程等当前开发工作优先把此项目作为候选。
- `375`：`APP装车及自动测试 v0.0.1`
  - 2026-08-01 实时读取为历史关闭项目（`status=closed`，周期 2019-11-01～2019-11-30）。
  - 无真实任务模块；创建页模块仅显示 `/`（值 `0`），提交任务会返回 `『Module』should not be blank.`。
  - 当时项目团队表/负责人下拉中有张召兵 `zhangzhaobing`，没有张斌 `zhangbin`。

## 必须遵循的消歧流程

1. 对口语项目名查询所有匹配项目，不要因为某个旧项目名称文字最接近就直接选它。
2. 同时展示项目 ID、完整名称、状态和是否可创建；当前活跃项目优先于历史关闭项目，但不能替用户做最终选择。
3. 若工作内容是 TYBox、Coze Workflow、头盔扫码/拍照装车，推荐 `1685`，并明确它与历史项目 `375` 的差异。
4. 用户只说“改成 APP 装车”且存在多个候选时，先让用户按项目 ID 确认；不要把这句话视为对某个具体项目的创建授权。
5. 创建前继续实时校验模块和负责人下拉。用户口头说某人是团队成员，但实时 `zt_team`/`assignedTo[]` 不一致时，报告差异并停止写入，除非用户明确改项目、改负责人或先修复项目配置。

## 批量任务的并发状态变化

批量创建部分成功、后续行因业务校验暂停时，先前成功任务可能被其他人立即录入工时。恢复批次时：

- 精确同名查重并复用已创建任务，不重复创建。
- 重新读取任务的当前 `consumed`、`left`、`status`。
- 当前 `left` 不再等于创建时 `estimate` 时，不应当作创建失败，也不要自动改回；应报告这是创建后的实时状态变化。
