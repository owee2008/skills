补充处理口径：

- 如果用户说“之前录的任务工时不够，差 N 小时”，先实时读取原任务状态。原任务已经 `done` 时，不要直接增加预计/剩余工时；草案中优先建议创建一条“补充调整”新任务，并明确原任务不修改，等用户确认。
- 用户对编号行给出“这些都是某项目、某端模块”时，这是整组行的项目/模块覆盖；更新每一行后重新展示完整最终清单。若回复只是字段修正而非“确认/创建”，仍等待最终创建确认。
- 工作文本里的系统名不一定等于禅道归属。对“我的日志嵌入人号管理/直播间”类工作，用户明确的交付端（如“我的日志项目，Web 端模块”）优先于被嵌入系统名称。

## Durable workflow lesson

When the user asks only to “分析属于哪个项目和模块”, treat the output as a mapping draft, not a creation or merge proposal. If the user later says “确认并创建禅道任务”, preserve the latest user-confirmed granularity. Do not merge same-project/module rows unless the user explicitly asks to合并; if the user says“不合并”, every row stays a separate task even if two rows share the same project/module.
